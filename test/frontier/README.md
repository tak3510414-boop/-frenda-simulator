# Frenda Frontier Ver0.50 / TEST

## Ver0.50 - 最小ゲームループ統合

Ver0.49で5エリア移動基盤を実機確認済みとし、次段階の **共通アイテム・経済・時間基盤 / 最小ダンジョン / 最小ショップ** を一体化した。

### 共通基盤
- ゲーム内時間を `朝 → 昼 → 夕方 → 夜` の4段階で管理。実時間には連動しない。
- 冒険帰還・営業など大きな行動で時間帯が進み、夜を越えると日数が進む。
- 日付更新時に建設工事も1段階進む。
- アイテム定義、倉庫、販売価格、売上、発展ptを共通APIから参照できるよう整理。
- save schemaVersion 14。旧Ver0.49セーブは自動移行。

### 最小ダンジョン
- `DUNGEON_DEFS` を導入し、最初の `はじまりの森` をデータ定義化。
- B1F〜B3F、採取、敵、相棒自動戦闘、バッグ、階段、帰還、ロープ、敗北時一部ロストを継続。
- 帰還時に素材を倉庫へ移し、時間と発展ptが進む。
- 踏破時はクリア報酬をダンジョン定義から付与。

### 最小ショップ
- 倉庫の商品を3つの棚へ移し、販売価格を設定。
- 営業すると4人の客が順番に来店し、予算・好み・価格から購入を判断。
- 購入しなかった客も来客数へ記録。
- 売上、所持金、評判、発展ptへ反映し、営業終了時に時間帯が進む。
- 店画面の下部に、棚状態・所持金・時間帯・直近の来客結果を実表示する。

### 最小1周
`相棒を選ぶ → はじまりの森へ出発 → 素材を持ち帰る → 棚へ並べる → 営業して売る → 発展ptが増える`

この1周を初めて完了すると `firstLoop` を記録する。

### 今回の実機確認
1. 冒険タブで相棒を選び、`はじまりの森 出発`。
2. 採取マスで何か拾い、階段から帰還またはロープで帰還。倉庫に素材が入る。
3. お店で棚1に素材を並べ、相場付近の価格で `営業`。
4. 1件以上売れ、所持金と発展ptが増え、ヘッダの時間帯が進めばOK。

## Ver0.46 - エリア出口タップを確実な移動操作に変更

Ver0.44までの「現在位置が出口判定内へ入ったら自動切替」だけに依存する方式を修正しました。

- 画面端の出口へ続く道をタップすると、そのタップを「出口へ移動する操作」として認識します。
- 主人公は出口の内側まで経路探索で歩き、到着後に指定された隣接エリアへ必ず切り替えます。
- 自動境界判定は残していますが、出口タップ時は位置判定の端数やセル境界に依存しません。
- 到着直後に逆方向へ自動で戻らないよう、通常の自動出口判定は従来どおり狭い範囲のままです。
- 経路探索・通行判定関数に areaId を明示できるようにし、RuntimeSceneと保存中エリアの食い違いを防ぎました。
- `data-app-version` / `F.VERSION` / renderer version を 0.46 に統一しました。

### 今回の実機確認
南の街道沿いで、画面上端の街道（「中心開拓地」方向）をタップしてください。
主人公が上端へ歩いた後、自動で中心開拓地へ切り替わればOKです。

# Frenda Frontier Ver0.44 / TEST

## Ver0.44 - 双方向エリア移動の実機修正

- `index.html` の `data-app-version` が 0.42 のまま残っていたため、Ver0.43のJSをアップロードしても iPhone / GitHub Pages が `?v=0.42` の旧JSを再利用できる状態だった問題を修正。`data-app-version=0.44` に更新。
- エリア切替判定を「目的地へ到着した最後の1回だけ」から、**歩行中の各ステップで出口領域へ入った瞬間に判定**する方式へ変更。
- 南の街道の北出口に入れば、タップした最終座標やグリッド端数に依存せず中心開拓地へ自動切替する。
- 二重切替防止用 `transitioning` 状態を追加。

### Ver0.44 実機確認
南の街道沿いで上端の街道へ歩く → 自動的に中心開拓地へ戻り、南入口付近から再開すればOK。

## Ver0.44 - RuntimeScene描画の一体化

Ver0.39で定義したエリア共通SceneSpecを、実際のゲームフィールドで使うRuntimeSceneへコンパイルする基盤を実装しました。

### 今回の主な変更

- `compileAreaScene()` を追加し、1つのSceneSpecから以下を一括生成
  - 通行可能領域
  - エリア入口・出口
  - 施設配置スロットと入口候補
  - 工事用領域
  - NPC活動域・ウェイポイント
  - ランドマーク枠
  - 物流・サービス領域
  - 将来拡張port
- 南の街道沿いを、Ver0.38の手描き仮マップから `scene-spec-v2` の自動生成マップへ変更
- 南の街道の通行判定も、個別ベタ書きではなく生成されたRuntimeSceneを使用
- NPC表示位置もSceneSpecのNPC活動域から生成
- 施設枠は「最終建物座標」ではなく、全体構成変更に耐えられる建設可能領域として表示
- エリア仕様画面でSceneSpecとRuntimeSceneの両方を検証
- `AREA_SCENE_SCHEMA` v2 / 世界構造 Ver6 / save schemaVersion 13

### 設計上の目的

今後、全体マップのバランス変更で道路や施設位置が変わっても、エリアごとの個別コードを書き直さないための基盤です。西の森・東の川辺・北の高台や、将来追加される未知のエリアも同じコンパイラへSceneSpecを渡すだけで、最低限遊べるフィールドを生成できます。

Ver0.44時点の生成マップは最終美術ではありません。地形・接続・通行・配置余地を実機で確認するための仮実マップです。全体構成確定後に正式背景・施設・当たり判定へ差し替えても、SceneSpec/RuntimeSceneのデータ構造は維持します。

### 配置

画像アセットは変更していません。ZIP内の `test/frontier/` の8ファイルを `/test/frontier/` へ上書きしてください。Ver0.33以降の既存PNGはそのまま使用します。
