## Ver0.51 - ポケモン主体の冒険へ構造変更

Ver0.50で「冒険→採取→帰還→陳列→販売→町発展」の最小ループが実機確認できたため、
Frontierの根本設計を **人間＋ピックで冒険する方式から、ポケモン自身が冒険する方式** へ切り替えた。

### 1. Frontier Pokémon Species Master
- 既存 MasterDB 1,066件をそのまま個別キャラクター化せず、`name_ja` を軸に **540種族** へ自動統合。
- 同じポケモンの複数ピックは1種族にまとめる。
- 種族ごとに以下を自動生成する。
  - タイプ
  - 基礎能力の中央値
  - Frontier内の強さ区分
  - AIアーキタイプ（接近／遠隔／守備／俊敏／待伏／支援／自由）
  - 代表画像・代表技
- 新規ファイル `frontier-pokemon.js` を追加し、仲間・敵・図鑑で同じ種族マスターを使う。

### 2. 仲間条件
Frontier内ではポケモンそのものを仲間として扱う。
仲間として探索に連れて行ける条件は複数方式に対応し、現在の基盤では以下を実装。

- フレンダ所持連携：その種族のピックを1枚以上所持している
- Frontierイベント：ゲーム内イベントから仲間解放できるAPI
- 物語：ストーリーで仲間になる枠
- TEST環境では、実データに仲間候補がない場合のみ6種のTEST候補を表示

同じ種族のピックを複数持っていても、仲間一覧には1匹分だけ表示する。
ゲーム画面ではピック番号・★ランクを表示しない。

### 3. ポケモンだけでダンジョン探索
- ダンジョンから人間主人公を削除。
- 選んだ **探索リーダーのポケモンを直接操作** する。
- 人間用HP・防具という考え方を撤去。
- ダンジョン内は探索リーダーHP / Lv / PP / 食料 / バッグで管理。
- 敵に隣接して進もうとすると、探索リーダーが直接技で攻撃する。
- 野生ポケモン側も同じ種族マスターから生成する。

### 4. 野生ポケモン自動生成
- `はじまりの森` は `forest` バイオームを使用。
- タイプと種族強さから出現候補を自動選出。
- B1F～B2Fは主に common / uncommon、B3Fから rare まで出現可能。
- 1,066件のピックを1件ずつ敵定義する必要はない。
- 敵AIは種族特性から共通アーキタイプへ割り当てる。

### 5. Frontier図鑑
- 野生ポケモンがフロアに出現すると遭遇記録へ追加。
- 「遭遇済み」と「仲間として選択可能」を別管理。
- 図鑑画面で、MasterDB 1,066件 → 540種族への統合数も確認できる。

### 6. セーブ移行
- save schemaVersion 15。
- Ver0.50以前の `partnerId` は、対応する種族を判定して `team.leaderSpeciesId` へ自動移行。
- 旧 `partnerId` は互換用ミラーとして残すが、Frontier内部の正本は種族ID。

## Ver0.46 - エリア出口タップを確実な移動操作に変更

Ver0.44までの「現在位置が出口判定内へ入ったら自動切替」だけに依存する方式を修正しました。

- 画面端の出口へ続く道をタップすると、そのタップを「出口へ移動する操作」として認識します。

- 経路探索・通行判定関数に areaId を明示できるようにし、RuntimeSceneと保存中エリアの食い違いを防ぎました。
- `data-app-version` / `F.VERSION` / renderer version を 0.46 に統一しました。

## Ver0.44 - RuntimeScene描画の一体化

Ver0.39で定義したエリア共通SceneSpecを、実際のゲームフィールドで使うRuntimeSceneへコンパイルする基盤を実装しました。

### 今回の主な変更

- `compileAreaScene()` を追加し、1つのSceneSpecから以下を一括生成
  - 通行可能領域
  - エリア入口・出口
  - 施設配置スロットと入口候補
  - 工事用領域
  - NPC活動域・ウェイポイント
  - ランドマーク枠
  - 物流・サービス領域
  - 将来拡張port
- 南の街道沿いを、Ver0.38の手描き仮マップから `scene-spec-v2` の自動生成マップへ変更
- 南の街道の通行判定も、個別ベタ書きではなく生成されたRuntimeSceneを使用
- NPC表示位置もSceneSpecのNPC活動域から生成
- 施設枠は「最終建物座標」ではなく、全体構成変更に耐えられる建設可能領域として表示
- エリア仕様画面でSceneSpecとRuntimeSceneの両方を検証
- `AREA_SCENE_SCHEMA` v2 / 世界構造 Ver6 / save schemaVersion 13

### 設計上の目的

今後、全体マップのバランス変更で道路や施設位置が変わっても、エリアごとの個別コードを書き直さないための基盤です。西の森・東の川辺・北の高台や、将来追加される未知のエリアも同じコンパイラへSceneSpecを渡すだけで、最低限遊べるフィールドを生成できます。

Ver0.44時点の生成マップは最終美術ではありません。地形・接続・通行・配置余地を実機で確認するための仮実マップです。全体構成確定後に正式背景・施設・当たり判定へ差し替えても、SceneSpec/RuntimeSceneのデータ構造は維持します。
